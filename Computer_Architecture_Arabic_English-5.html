Memory & Cache – الذاكرة

تعريف Cache Hit و Cache Miss وحساب النسب.

Cache Hit

يحدث عندما يجد المعالج البيانات المطلوبة داخل Cache Memory. الوصول يكون أسرع عادةً.

Cache Miss

يحدث عندما لا يجد المعالج البيانات المطلوبة في Cache، فيحتاج إلى جلبها من مستوى ذاكرة آخر مثل RAM.

القوانين

Hit Ratio = Hits ÷ Total Requests

Miss Ratio = Misses ÷ Total Requests

Miss Ratio = 1 − Hit Ratio

لتحويل النسبة إلى مئوية نضرب في 100.

مثال محلول

200 requests, 150 hits.

Hit Ratio = 150 ÷ 200 = 0.75 = 75%

Misses = 200 − 150 = 50

Miss Ratio = 50 ÷ 200 = 25%

حاسبة Hit / Miss

تمارين

  1. 500 requests, 400 hits. Find Hit and Miss Ratios.
  2. 300 requests, 240 hits. Find Hit and Miss Ratios.
  3. 1000 requests, 200 misses. Find Hit and Miss Ratios.
  4. L1=50, L2=30, L3=15, RAM=5, total=100. Find total cache hit ratio and miss ratio.
إظهار الإجابات

1) 80%, 20%   2) 80%, 20%   3) 80%, 20%   4) 95%, 5%.

Hamming Code

يضيف Check Bits (Parity Bits) إلى البيانات للمساعدة على اكتشاف وتصحيح خطأ بت واحد وفق طريقة Hamming القياسية.

القوانين

2ʳ ≥ m + r + 1

n = m + r

m = number of data bits; r = check bits; n = total codeword bits.

مثال: m = 4

Try r = 2: 2² = 4, but m+r+1 = 7 → not enough.

Try r = 3: 2³ = 8 and m+r+1 = 8 → valid.

r = 3, n = 4 + 3 = 7

أماكن Parity: 1 و2 و4. توضع البيانات في المواقع الباقية.

مجموعات الفحص مع Even Parity

  • P1 checks positions 1, 3, 5, 7, 9, ...
  • P2 checks positions 2, 3, 6, 7, 10, 11, ...
  • P4 checks positions 4, 5, 6, 7, 12, 13, 14, 15, ...

عند الاستقبال، تجمع نتائج الفحص على شكل S4S2S1 لتحصل على موقع الخطأ (إذا كان هناك خطأ واحد).

Hamming Practice

  1. For m=4, find r and n.
  2. For m=8, find the minimum r and n.
  3. For m=5, find r and n.
  4. If syndrome S4S2S1 = 110, find the error position.
إظهار الإجابات

1) r=3, n=7
2) r=4, n=12
3) r=4, n=9 (because 2⁴ ≥ 5+4+1)
4) 110₂ = position 6.

CRC – Code Word

إيجاد الباقي باستخدام القسمة الثنائية XOR ثم تكوين Code Word.

التعريفات

  • Data Word: البيانات الأصلية.
  • Divisor / Generator: المقسوم عليه الثنائي.
  • Remainder: الباقي من القسمة.
  • Code Word: البيانات الأصلية متبوعة بالباقي.

القانون

n = k + (m − 1)

k = data-word length; m = divisor length; remainder length = m−1; n = codeword length.

قواعد XOR

ABA XOR B
000
011
101
110

لا يوجد حمل أو استعارة في XOR.

مثال محلول من الدفتر

Data Word = 1001; Divisor = 1011

m = 4 → m−1 = 3 zeros

Augmented data = 1001000

Modulo-2 division by 1011 gives remainder 110.

Code Word = 1001 + 110 = 1001110

حاسبة CRC تفاعلية

استخدم بتات 0 و1 فقط، ويجب أن يكون المقسوم عليه بطولين أو أكثر.

تحويل Polynomial إلى Divisor

G(x) = x³ + x + 1

Coefficients from x³ to x⁰: 1, 0, 1, 1

Divisor = 1011

اكتب 1 إذا كان الحد موجوداً و0 إذا كان غير موجود، مع ترتيب القوى تنازلياً دون حذف قوة.

CRC Practice

  1. Data=1010, Divisor=1011. Find remainder and codeword.
  2. Data=1101, Divisor=1011. Find remainder and codeword.
  3. G(x)=x³+x²+1. Write the divisor.
  4. G(x)=x⁴+x+1. Write the divisor.
إظهار الإجابات

1) Remainder 011; Codeword 1010011.
2) Remainder 001; Codeword 1101001.
3) 1101.
4) 10011.

المحاضرة الثانية: Cache Hit وCache Miss

Hit Ratio, Miss Ratio & Multi-level Cache

Cache Memory

الكاش ذاكرة سريعة تحتفظ بنسخ من البيانات والتعليمات المستخدمة كثيراً حتى لا يضطر المعالج إلى الرجوع إلى RAM في كل مرة. يبحث المعالج عادةً بالتسلسل: L1 ثم L2 ثم L3 ثم RAM.

Cache Hit

يعني أن المعالج وجد البيانات المطلوبة داخل أحد مستويات Cache. لذلك يحصل عليها بسرعة ولا يحتاج إلى جلبها من RAM.

Hit = Found in Cache

Cache Miss

يعني أن البيانات غير موجودة في مستوى الكاش الذي تم فحصه. ينتقل البحث إلى المستوى التالي، وإذا لم توجد في L1 وL2 وL3 تُجلب من RAM.

Miss = Not Found at that level

مثال محلول 1: حساب Hit Ratio وMiss Ratio

CPU made 20 memory requests. 15 requests were cache hits.

  1. نحدد المعطيات: Total Accesses = 20، وعدد Hits = 15.
  2. نستخدم القانون: Hit Ratio = Number of Hits ÷ Total Accesses.
  3. Hit Ratio = 15 ÷ 20 = 0.75
  4. لتحويل العدد العشري إلى نسبة مئوية نضرب في 100: 0.75 × 100 = 75%.
  5. Miss Ratio = 1 − Hit Ratio = 1 − 0.75 = 0.25 = 25%.
Hit = 75% | Miss = 25%

لماذا نطرح من 1؟ لأن مجموع نسبة النجاح ونسبة الإخفاق يساوي 100%، أي 1.

مثال محلول 2: ثلاث مستويات Cache

100 requests: L1 serves 60, L2 serves 25 of the remaining requests, L3 serves 10 of the remaining requests, and 5 go to RAM.

  1. نبدأ بـ 100 طلب. المستوى الأول وجد 60 طلباً؛ إذن L1 Hit = 60.
  2. المتبقي بعد L1 هو 100−60=40. من هذه الأربعين وجد L2 عدد 25.
  3. المتبقي بعد L2 هو 40−25=15. وجد L3 عدد 10.
  4. المتبقي بعد L3 هو 15−10=5، وهذه الطلبات تذهب إلى RAM.
  5. مجموع Cache Hits = 60+25+10=95. نقسم على مجموع الطلبات 100.
Total Hit Ratio = 95/100 = 95%
Miss Ratio = 5/100 = 5%

انتبه: في مثال المستويات، أعداد L2 وL3 محسوبة من الطلبات المتبقية كما صيغ المثال في المحاضرة، وعند حساب النسب لكل مستوى بالنسبة إلى إجمالي الطلبات نقسم على 100.

تمارين المحاضرة الثانية

  1. 300 memory requests, 240 hits. Find Hit Ratio and Miss Ratio.
  2. 500 requests, 425 hits. Find both ratios.
  3. 100 requests: L1=50, L2=30, L3=15, RAM=5. Find total hit and miss ratios.
الحلول خطوة بخطوة

1) Hit=240÷300=0.8=80%. Miss=1−0.8=20%.

2) Hit=425÷500=0.85=85%. Miss=15%.

3) Total hits=50+30+15=95. Hit=95/100=95%. Miss=5/100=5%.

المحاضرة الثالثة: Hamming وFloating Point وBCD

Error Detection & Data Representation

Hamming Code — الفكرة

نضيف بتات فحص تسمى Parity Bits إلى بتات البيانات حتى نكتشف الخطأ، ويمكن في كود Hamming تصحيح خطأ واحد. إذا كان عدد بتات البيانات m وعدد بتات الفحص r، فإن طول الكلمة النهائية n=m+r.

Formula: 2ʳ ≥ m + r + 1

نستخدم أصغر قيمة r تحقق المتباينة؛ لأننا نريد أقل عدد ممكن من بتات الفحص.

مثال: m=4

  1. نجرب r=2: 2²=4، والطرف الآخر 4+2+1=7؛ الشرط غير متحقق.
  2. نجرب r=3: 2³=8، والطرف الآخر 4+3+1=8؛ الشرط متحقق.
  3. إذن r=3، وطول Code Word هو n=4+3=7 bits.

إنشاء Hamming Code للبيانات 1011

  1. لدينا m=4، لذلك نحتاج r=3. طول الكلمة n=7.
  2. نرقم الخانات من اليمين إلى اليسار ابتداءً من 1. خانات القوى 2 هي 1 و2 و4، وهذه أماكن parity.
  3. نضع البيانات 1011 في الخانات الباقية: 3 و5 و6 و7. تصبح الخانات من 7 إلى 1: 1 1 0 P4 1 P2 P1.
  4. نستخدم Even Parity: يجب أن يكون عدد الـ 1 في كل مجموعة زوجياً.
  5. P1 يفحص الخانات 1 و3 و5 و7. البيانات فيها 0 و1 و1؛ عدد الواحدات 2، لذلك P1=0.
  6. P2 يفحص الخانات 2 و3 و6 و7. البيانات 1 و1 و1؛ عدد الواحدات 3، لذلك نضيف P2=1 ليصبح العدد 4.
  7. P4 يفحص الخانات 4 و5 و6 و7. البيانات 0 و1 و1؛ عدد الواحدات 2، so P4=0.
Code Word = 1100110

ملاحظة: المثال يستخدم Even Parity. إذا طلب السؤال Odd Parity تتغير قيم بتات الفحص حتى يصبح عدد الواحدات فردياً.

Floating-Point — النموذج المبسط بالمحاضرة

العدد العائم يخزن الأعداد الكبيرة أو الكسور باستخدام صيغة تشبه الكتابة العلمية. نموذج المحاضرة يتكون من 14 بت: بت إشارة واحد، 5 بت للأس، و8 بت للـ Significand.

  • Sign: 0 للموجب و1 للسالب.
  • Exponent: يحدد مجال الأعداد الممكن تمثيلها.
  • Significand: يؤثر في دقة التمثيل.

مثال تخزين 17 حسب نموذج المحاضرة

  1. 17₁₀ = 10001₂.
  2. نحرك الفاصلة الثنائية حتى نحصل على الشكل المستخدم بالمحاضرة: 0.10001 × 2⁵.
  3. نملأ 8 بت للـ Significand: 10001000.
  4. في النموذج الذي لا يستخدم Bias، الأس 5 بالثنائي هو 00101.
  5. إذا استخدمنا Excess-15 كما تشرح المحاضرة، نضيف Bias=15 إلى الأس الحقيقي: 5+15=20، و20 بالثنائي 10100.

انتبه: اتبع صيغة السؤال؛ هل يطلب النموذج الأول أم نموذج Excess-15؟ لا تخلط بين الأس الحقيقي والأس المخزن.

BCD — Binary-Coded Decimal

في BCD لا نحوّل العدد العشري كله مرة واحدة إلى ثنائي. نحول كل رقم عشري بمفرده إلى 4 بتات.

Example: 146₁₀

  1. 1 → 0001
  2. 4 → 0100
  3. 6 → 0110
  4. نضع المجموعات بالترتيب نفسه.
146 in BCD = 0001 0100 0110

الفرق المهم: 146 بالثنائي العادي = 10010010، أما BCD = 0001 0100 0110. لا تخلط بينهما.

تمارين المحاضرة الثالثة

  1. Find the number of Hamming check bits for m=5.
  2. Construct Hamming code for data 1001 using even parity.
  3. Convert 59₁₀ to binary and express it in the lecture's floating-point form.
  4. Convert 275₁₀ to BCD.
عرض الحلول

1) Try r=3: 8 ≥ 5+3+1=9 (false); r=4: 16 ≥ 5+4+1=10 (true). So r=4.

2) Positions 1,2,4 parity; data in 3,5,6,7. P1=0, P2=0, P4=1; code word from bit 7 to 1 = 1001100.

3) 59₁₀=111011₂=0.111011×2⁶. Pad significand as needed according to the 8-bit field: 11101100. Sign=0. (For Excess-15, stored exponent=6+15=21=10101.)

4) 2→0010, 7→0111, 5→0101. BCD=0010 0111 0101.

المحاضرة الرابعة: CRC وCode Word

Generator / Divisor / Remainder

CRC — Cyclic Redundancy Check

تقنية لاكتشاف الأخطاء في البيانات أثناء النقل أو التخزين. نضيف بتات فحص إلى البيانات الأصلية. في قسمة Modulo-2 نستخدم XOR بدلاً من الطرح الاعتيادي.

قواعد XOR الضرورية

0 XOR 0 = 0 · 1 XOR 1 = 0 · 0 XOR 1 = 1 · 1 XOR 0 = 1

يعني إذا البتان متشابهان فالنتيجة 0، وإذا مختلفان فالنتيجة 1. وعند القسمة نهمل الصفر الأول في الناتج الجزئي وننزل البت التالي.

مثال الدفتر: Data Word=1001 وDivisor=1011

  1. Data Word هي البيانات الأصلية: 1001.
  2. Divisor هو المقسوم عليه أو Generator: 1011. طوله 4 بتات، إذن m=4.
  3. نحسب m−1 = 4−1 = 3. لذلك نضيف ثلاثة أصفار إلى نهاية Data Word.
  4. تصبح البيانات الموسعة Augmented Data = 1001000.
  5. نقسم 1001000 على 1011 باستخدام XOR. في كل خطوة نقارن مجموعة من 4 بتات مع 1011 إذا كان أول بت 1، وإذا كان 0 نستخدم 0000، ثم ننزل البت التالي.
  6. بعد إكمال القسمة يكون الباقي 3 بتات لأن طول المقسوم عليه 4، والباقي طوله m−1=3: وهو 110.
  7. نلصق الباقي بنهاية البيانات الأصلية، وليس بنهاية البيانات الموسعة: 1001 + 110.
Remainder = 110
Code Word = 1001110

احفظ ترتيب الفكرة: طول Divisor ← m−1 أصفار ← قسمة XOR ← Remainder ← نضيفه إلى Data Word الأصلية.

كيف أستخرج Divisor من Generator Polynomial؟

نكتب معاملات الحدود من أعلى قوة إلى x⁰. إذا كان الحد موجوداً نكتب 1، وإذا كانت القوة ناقصة نكتب 0.

  1. G(x)=x³+x+1 → القوى: x³, x², x¹, x⁰ → المعاملات 1,0,1,1 → 1011.
  2. G(x)=x³+x²+1 → المعاملات 1,1,0,1 → 1101.
  3. G(x)=x⁴+x+1 → المعاملات 1,0,0,1,1 → 10011.

لا تترك خانة القوة الناقصة فارغة؛ ضع مكانها صفراً.

تمارين المحاضرة الرابعة

  1. Data=1010, Divisor=1011. Find the augmented data, remainder and code word.
  2. Data=1101, Divisor=1011. Find the remainder and code word.
  3. Find the divisor for G(x)=x⁴+x²+1.
  4. Divisor length is 5 bits. How many zeros do we append?
الحلول مع التفسير

1) Divisor length=4, so append 3 zeros: 1010000. Remainder=011. Code Word=1010011.

2) Append 3 zeros: 1101000. Remainder=001. Code Word=1101001.

3) Powers x⁴,x³,x²,x¹,x⁰ → 1,0,1,0,1 = 10101.

4) m−1=5−1=4 zeros.

طريقة المحاضرة للتحويل

طريقة 1، 2، 4، 8، 16، 32، 64

هذه هي أوزان الخانات الثنائية (Place Values)، ونستخدمها خصوصاً عند التحويل من Binary إلى Decimal.

أولاً: لماذا تظهر هذه الأرقام؟

كل خانة في النظام الثنائي تساوي قوة من قوى العدد 2. نبدأ من أقصى اليمين بالقيمة 2⁰=1، ثم نتحرك يساراً ونضاعف القيمة: 2، 4، 8، 16، 32، 64، وهكذا. لذلك ترتيب الأوزان من اليمين إلى اليسار هو 1، 2، 4، 8، 16، 32، 64.

مثال خطوة بخطوة: حول (1101011)₂ إلى Decimal

الخطوة 1: اكتب أوزان الخانات من اليمين إلى اليسار تحت البتات.

Bits:   1   1   0   1   0   1   1
Weights: 64   32   16   8   4   2   1
  1. الخطوة 2: كل خانة تحتوي 1 نأخذ وزنها، وكل خانة تحتوي 0 نهمل وزنها.
  2. 64 + 32 + 0 + 8 + 0 + 2 + 1
  3. الخطوة 3: نجمع الأوزان التي اخترناها: 64+32+8+2+1=107.
(1101011)₂ = (107)₁₀

الفكرة المهمة: لا تجمع كل الأرقام؛ اجمع فقط الأوزان التي يقابلها البت 1.

الطريقة العكسية: من Decimal إلى Binary باستخدام الأوزان

مثال: حول 45 إلى Binary. نختار أكبر وزن لا يتجاوز 45 ثم نطرح، ونكرر مع الأوزان الأصغر.

WeightDecisionRemaining value
3245 ≥ 32 → 145−32 = 13
1613 < 16 → 013
813 ≥ 8 → 113−8 = 5
45 ≥ 4 → 15−4 = 1
21 < 2 → 01
11 ≥ 1 → 11−1 = 0
45₁₀ = 101101₂

تمارين على طريقة الأوزان

  1. حوّل (101101)₂ إلى Decimal.
  2. حوّل (1110010)₂ إلى Decimal.
  3. حوّل 38₁₀ إلى Binary باستخدام الأوزان.
الحلول مع خطوات الجمع والطرح

1) 32+8+4+1 = 45.

2) 64+32+16+2 = 114.

3) 38−32=6، 16 لا تدخل، 6−4=2، 2−2=0 → الأوزان 32,4,2 مختارة → 100110₂.

Q1 / Hit and Miss

A: اشرح عمليتي Hit وMiss بالتفصيل مع مخطط انسيابي

يصدر المعالج طلباً لعنوان ذاكرة. يفحص Cache L1 أولاً. إذا وجد البيانات (Hit) يرسلها للمعالج. إذا لم يجدها (Miss) ينتقل إلى L2 ثم L3. إذا لم توجد في أي مستوى، يجلبها من RAM ثم يخزن نسخة منها في Cache.

CPU Memory Request
↓
Check L1 Cache
↓
Data found?
Yes → HIT

Send data to CPU

No → MISS

Check L2, then L3

Not found in cache? → Fetch from RAM
↓
Update Cache → Continue CPU

B: المعالج نفذ 20 طلب ذاكرة، وجميع الطلبات العشرين وُجدت في Cache

  1. المعطيات: Total Requests=20، Hits=20.
  2. قانون Hit Ratio = عدد Hits ÷ مجموع الطلبات.
  3. Hit Ratio = 20 ÷ 20 = 1 = 100%.
  4. عدد Miss = مجموع الطلبات − Hits = 20−20=0.
  5. Miss Ratio = 0 ÷ 20 = 0 = 0%.
Hit Ratio = 100% | Miss Ratio = 0%

ملاحظة: في ورقة الامتحان مكتوب 20 requests found in cache، أي كل الطلبات Hits، وليس 15 من 20.

Q2 / Floating Point & Computer Levels

A: Express (16)₁₀ in the simplified 14-bit floating-point model with Excess-15 bias

تقسيم النموذج حسب المحاضرة: 1 بت للإشارة Sign، و5 بت للأس Exponent، و8 بت للـ Significand، المجموع 14 بت.

  1. حوّل 16 إلى ثنائي: 16=10000₂.
  2. اكتب العدد بالشكل المعياري المستخدم في هذا النموذج: 0.10000 × 2⁵. إذن الأس الحقيقي E=5.
  3. Sign=0 لأن العدد موجب.
  4. Excess-15: الأس المخزن = E + Bias = 5+15=20. نحول 20 إلى 5 بت: 10100.
  5. Significand من 8 بت: نكتب 10000 ثم نكمل أصفاراً إلى 8 بت = 10000000.
0 | 10100 | 10000000

النتيجة النهائية 14 بت: 01010010000000. (اعتمدنا تمثيل المحاضرة 0.1xxxx × 2^E).

B: List the computer-level steps

هذه المستويات كما وردت في المحاضرة الثانية، من المستوى 0 إلى المستوى 6:

  1. Level 0 – Digital Logic: الدوائر الرقمية والبوابات والأسلاك التي تنفذ المنطق.
  2. Level 1 – Control Level: وحدة التحكم تفكك التعليمات وتنفذها وتنقل البيانات.
  3. Level 2 – Machine Level (ISA): تعليمات لغة الآلة الخاصة بمعمارية الحاسوب.
  4. Level 3 – System Software: إدارة العمليات وحماية موارد النظام.
  5. Level 4 – Assembly Language: مستوى لغة التجميع.
  6. Level 5 – High-level Language: لغات مثل C وPascal وJava.
  7. Level 6 – User Level: مستوى تشغيل البرامج وواجهة المستخدم.

Q3 / CRC Verification

Given: Received code word = 1001, G(x)=x³+x+1.

  1. نحوّل كثير الحدود إلى Divisor: نرتب القوى x³، x²، x¹، x⁰. معاملات الحدود هي 1،0،1،1؛ إذن Divisor=1011.
  2. للتحقق من Code Word مستلم، نقسم الكلمة المستلمة نفسها 1001 على 1011 باستخدام Modulo-2 (XOR).
  3. نقارن 1001 مع 1011: 1001 XOR 1011 = 0010. بعد حذف الأصفار اليسرى يبقى 10، ونكتب الباقي بطول 3 بتات: 010.
  4. الباقي ليس صفراً، إذن توجد إشارة إلى خطأ في الكلمة المستلمة.
Remainder = 010 → Error detected

قاعدة التحقق: إذا كان Remainder=000 فلا يظهر خطأ حسب CRC؛ وإذا كان غير صفر فهذا يدل على خطأ محتمل. CRC يكشف الخطأ ولا يحدد وحده أي بت يجب تغييره.

Q5 / Hamming Code

Given: 4-bit data word = 1010. Assume even parity and standard Hamming positions numbered from right to left.

  1. لدينا 4 بتات بيانات. نحتاج 3 بتات فحص لأن 2³ ≥ 4+3+1، فيكون طول الكلمة 7 بتات.
  2. أماكن الفحص هي 1 و2 و4. نضع البيانات في المواقع 3 و5 و6 و7. من الموقع 7 إلى 3 تكون البيانات 1،0،1،0.
  3. P1 يفحص المواقع 1،3،5،7. البيانات المعروفة 0،1،1 فيها وحدتان 1، إذن P1=0.
  4. P2 يفحص المواقع 2،3،6،7. البيانات 0،0،1 فيها واحد فقط، لذلك نضع P2=1 حتى يصبح العدد زوجياً.
  5. P4 يفحص المواقع 4،5،6،7. البيانات 1،0،1 فيها وحدتان 1، إذن P4=0.
Codeword (positions 7→1) = 1010010

الآن نراجع عبارة السؤال: «bit position 6 is changed to (0)». حسب ترقيم Hamming القياسي من اليمين، الموقع 6 في الكلمة الأصلية قيمته 0 أصلاً. لذلك تغييره إلى 0 لا يغيّر شيئاً، وتكون Syndrome=000 ولا يوجد خطأ فعلي وفق هذا التفسير.

تنبيه مهم حول صياغة السؤال

قد يكون المقصود ترقيم البتات من اليسار، أو قد توجد زلة في نص السؤال. إذا كان المقصود قلب البت السادس من اليمين، فيجب أن يكون تغييره من 0 إلى 1، وليس إلى 0. لذلك لا يصح اختراع خطأ أو موضع تصحيح دون تثبيت طريقة الترقيم التي يعتمدها المدرس.
